# 多从站启动优化与 1 ms App 移植

用于 IgH 多从站初次进入 OP 慢、初始化顺序控制与启动密集校时策略评估，以及把诊断措施移植到真实 App。
这是 2026-09-18 的历史证据与复用方法，不描述当前在线状态，不授予连接、修改或使能权限。
不保存凭据。参数与补丁按新现场的实际 IgH/ESC 实现重新核对。

新现场先按 [现场检查顺序](field-workflow-and-tools.md) 核对周期和相位；本页聚焦 143 的历史组合。
后续 [193 两站案例](case-193-phase-and-burst.md) 在实验前模块上采用相位＋应用层策略通过，
说明不能把本页初始化顺序补丁视为通用前置条件。

## 案例编号、实现层次与复用条件

K4 和 B1 是原现场给候选实现使用的标签，分别表示本页 B 节的“初始粗校正完成后放行周期校时”
和 C 节的“启动阶段有界密集校时”。它们不是协议功能名，也不是上游 IgH 的版本号或命令行开关。

- **K4（IgH 主站模块改动）**：在激活时建立初始化完成标志，初始 offset 流程完成后放行参考时钟
  与从站的周期校正报文。历史版本还包含前序 offset 处理及非参考站滤波复位，不能把全部成果归因于
  单个门控改动。复现需要匹配现场源码和内核构建环境，重新构建并替换 IgH 模块；无需重编整个 Linux 内核。
- **B1（应用层改动）**：在启动等待阶段增加独立 receive／校时／send 时隙，保持正常 PDO 周期。
  原案例使用 1 ms PDO、前 4 秒、每毫秒额外四个时隙；这些是实验参数，不是跨设备默认值。

两者在实现上分属两层，在本页 143 的性能证据上不能拆开归因。本页测试的 B1 运行在 K4 上，由 K4 阻止
初始 offset 未完成时真正排入周期校时报文。额外收发机会也可能推进配置状态机。
原版 IgH 上可以评估应用层密集校时，但需重新检查它的初始 offset 与周期校时交互，不能假定已有
K4 的完成标志或门控，也不能用固定等待时间假装已经确认初始化完成。

新现场先保留现有 IgH 建立基线；应用层方案若适用则独立验证。只有证据指向初始化交互且获准修改
主站模块时，才评估 K4 类处理。若要比较因果，在相同接线、参考站、周期、冷/热启动条件和验收窗口下，
按实际需要比较基线、仅应用层密集校时、仅初始化顺序控制及组合方案；保留所有失败轮次。
本页没有“原版 IgH＋B1”的实测结论，K4 单独也没有明显缩短本轮完整冷启动耗时。

移交本技能文件夹即可阅读这些方法；第 4 节的原现场路径和哈希仅作追溯，不是新现场的依赖。
精确复现历史二进制另需相应源码/补丁归档，不能把目录名或版本代号当作已安装的功能。

## 1. 先固定因果链与测量定义

本案例以主机应用时间校正参考 ESC，再由参考 ESC 给其他 ESC 提供同步基准。
方向为“主机给参考站校时；其他站跟随参考站”，不是主机周期读取 PDO 时间去追从站。
应从实际 ecrt_master_application_time、参考校时与从站同步 API 的使用确认方向。

区分传播延迟补偿、初始系统时间 offset、持续频率/相位调节及应用稳定窗口。
传播延迟不是凭经验增减的启动时间；offset 也不等于周期线程 jitter。
启动时主从有初始时间差，后续还可能有频率差、滤波/调节状态和状态机等待，不能假设一次相减即可全部结束。

时间记录至少覆盖：实时循环起点、WKC 完整、八站全 OP、持续 DC 达标、应用 READY。
本案例表中时间从后端循环起点计算，不含上电等待、桌面点击、前置扫描/部署耗时。
IgH 聚合监测不是逐站 0x092C 绝对值的算术最大值；分站、聚合、线程迟到和 SYNC0 边沿测量分别报告。

## 2. 复用策略及其边界

### A. 统一时基和发送时序

不要求外部 UTC/PTP 且主机驱动参考 ESC 时，可评估 RAW 应用时间并令周期期限跟随 RAW。
每次睡眠配对读取 RAW/MONOTONIC，把 RAW 绝对期限映射到 MONOTONIC 绝对睡眠；处理读数延迟、
睡眠错误、中断和超期，不能只改 API 时间参数。实测 MONOTONIC/RAW 相对频差作为证据，不能仅凭它断言唯一根因。
固定校时戳到发送的路径，区分 queue、send 调用返回与实际网卡出线。实时优先级/绑核按现场评估；
本案例 CPU6、FIFO80 不是可跨机器照搬的设置。

日志移出实时线程在早期单轴案例已实施；此次多轴 App 仍有实时线程的 dashboard 输出，不能宣称
该项已完整移植。若后续改日志，保留关键会话协议并验证背压，不能将协议事件作为可丢遥测。

### B. 先粗校正，再放行循环同步：K4

案例补丁在 Master0 激活时清零 dc_initial_sync_ready；初始 offset 扫描/写入完成后置位。
在此之前，参考校时（含指定时间版本）及从站同步 API 暂不排入周期校正报文；
PDO、配置状态机和应用时间更新继续。不要把整个通信循环停掉等待 DC。
该门控针对激活时的初始化，不自动在 OP 运行中扫描或重写 offset。

该组合继承了初始 offset 校正后非参考站滤波复位、参考站滤波状态保留的实验处理。
参考站与跟随站不能一律复位；先核对 ESC 和本机 IgH 的实际实现，不提供跨型号通用寄存器写值。
检查门控完成条件/激活复位点以及超时退出，避免新设备因状态条件不同而永远不放行。

结果支持初始误差有改善，**K4 单独没有明显缩短本轮完整冷启动耗时**。不能仅根据机制合理就宣称性能有效。

### C. 启动密集校时：B1

在已完成初始 offset 的基础上，仅启动阶段前 4 秒增加校时机会。案例配置：

- PDO 基本周期 1 ms；正常一轮发送之外，在 200/400/600/800 µs 四个绝对时隙分别发送。
- 每个额外时隙执行 receive、更新 RAW 应用时间、排参考校时与从站同步、独立 send。
- 额外时隙不重复 queue PDO；不把控制周期改成 200 µs。
- 错过或睡眠过迟的时隙跳过，不积压补发；处理 receive/时钟/send 失败和退出信号。
- 限制在启动等待 OP/DC 的阶段；使能阶段、故障退出及停止期间不执行启动 burst。
- 到时恢复常规 1 kHz 校时。记录额外发送次数、跳过次数、调用耗时，不能将这些数值等同于硬件出线时刻。

不是扫描任意 offset/相位值，也不是调大启动时间。额外发送可能同时推进 IgH 配置状态机交互，
不能把全 OP 加速全部归因于 ESC 频率环路。对新设备需测实际 PDO 更新与看门狗行为，不能禁用看门狗掩盖失败。

### D. 拓扑、周期与 App 集成

本次实际拓扑为传感器正接且物理位置0，七电机位置1～7；传感器作参考。用户界面的逻辑轴仍为0～6。
反接与参考站选择不是通用禁令：应先核对端口方向、帧路径、传播延迟计算及设备支持，不凭物理摆放推断枚举序号。
精确校验站数、身份、位置、参考站、PDO 配置及模块版本，拒绝把别的拓扑套入固定映射。

本用户要求后续 Sophon Force 方案统一 1 ms。最终 CSP/PDO/SYNC0 均1ms；案例传感器 shift500µs、
电机 shift0、SYNC1未启用。这些相位是案例参数，不是其他传感器/驱动的通用建议。
移植时查清实际桌面入口 → 固定启动器 → 已安装后端的哈希；不要只修改 jgh 等旁路诊断程序。
由500Hz改1000Hz时换算：准备500ms、快速停止200ms、shutdown100ms、到位稳定100ms、监测/轮询100ms。
轨迹累积器保持界面deg/s含义及限幅；旧counts-per-cycle参数若兼容，说明其原有时间单位。

配置扫描、精确 PDO allowlist 准备在实时循环建立前完成。案例 allowlist 是该传感器固定PDO的特定机制，
不是通用优化；共享模块参数/重载的影响范围可能跨主站，应遵守本次范围，不借迁移扩大到其他主站。

### E. 真实达标和复测

只消费有效新鲜监测样本，并要求每个目标站OP、模式正确、WKC完整；失效清零稳定计数。
保持原验收门槛，不通过缩短人为稳定窗口制造“更快”。持续窗口用采样间隔解释，不能按缓存值每周期累计。
记录每站AL状态；WKC24、很小的DC偏差、无CiA402 fault、返回码0均不能单独代表八站通过。
区分运行期间的 AL 错误与停止发帧/释放主站后的错误，保留两类日志。

实际 App 后端提供有界 --check：控制字强制0，禁止自动故障复位，持续检测OP/WKC/DC及意外使能。
测试失败保留结果并先判断是否安全复测；不要用自动反复启动覆盖首次失败或把热启动记为冷启动。
新旧二进制、入口和UI哈希及完整源码隔离保存；实际验证安装→恢复→再安装，不依赖重新编译旧版才能回退。
恢复脚本需说明恢复范围：文件恢复成功不代表历史周期/接线配置适配现在的设备。

## 3. 实验结果：不得省略失败样本

### 独立 CST 诊断

判据：八站OP、WKC24、有效聚合DC≤15µs连续1秒；采样约50ms。

| 条件 | 运行时长 | 全OP | 连续达标 | 结论 |

| K4，无B1，主机＋从站冷启动 | 180s | 13.202s | 18.252s | 未明显缩短此前约18s尾段 |
| K4＋B1，仅从站再次断电冷启动 | 180s | 4.252s | 5.302s | 达标后未见OP/WKC/DC失锁 |
| B1初次热启动 | 45s | 2.852s | 3.852s | 通过 |
| B1重复热启动01 | 60s | 3.402s | 4.402s | 通过 |
| B1重复热启动02 | 60s | 未达到 | 未达到 | J6物理6，AL0x001B，SyncManager watchdog |
| B1重复热启动03 | 60s | 2.852s | 3.902s | 通过 |
| B1重复热启动04 | 60s | 2.852s | 3.902s | 通过 |

冷启动两条样本相差约12.95s，但主机是否重启不同且各一次，不能作为严格同条件71%收益保证。
B1冷启动15s后电机逐站0x092C绝对值峰值484～570ns、传感器928ns；不可与全启动峰值或聚合值混算。
失败轮J6未进OP，WKC后来已24且15s后各站偏差最大535ns；进程返回0也不改变失败结论。
失败轮软件唤醒/发送耗时正常不足以证明硬件PDO出线间隔正常；watchdog根因未定位。

### Sophon Force CSP App 迁移

最终周期1ms；门槛保留App的10µs、100ms间隔20个连续有效样本，不能与CST的1s窗口直接比较。

| 条件 | 时长 | 全OP | 连续达标 | 达标后聚合DC峰值 | 结论 |
|---|---:|---:|---:|---:|---|
| 早期2ms PDO＋1ms传感器SYNC0 | 60s | 未达到 | 未达到 | 不适用 | 传感器AL0x001A；候选未部署 |
| 最终1ms隔离构建，热启动 | 60s | 2.824s | 4.801s | 1023ns | 通过 |
| 同一1ms安装版＋真实前置检查，热启动 | 180s | 2.993s | 4.901s | 1023ns | 通过 |

周期不一致候选失败后曾构建2ms对齐候选，仅离线测试；用户要求1ms后最终部署上表1ms版。
两轮额外校时send调用各15996次；独立诊断记录16000次，不能混写。运行时抽查传感器、首台/末台电机
0x09A0均1000000ns。已验证原版入口恢复和再次安装；旧版恢复会回到历史2ms与旧轴排列，K4内核不回滚。

使能能力与验证分开：原App的MOVE→500ms位置准备→CiA402使能→CSP运动→目标保持逻辑被保留；
连接至READY不会自动使能七轴。测试只运行禁使能检查，不可报告已验证实际使能或运动。
App冷启动、带负载长期稳定性与物理SYNC0尚未验证；此前CST的watchdog失败不能被两轮App通过抹掉。
